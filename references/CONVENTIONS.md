# CONVENTIONS · 如何维护本 Skill

## 结构

| 层 | 文件 | 规则 |
|---|---|---|
| 路由层 | `SKILL.md` | 只放适用范围、红线、流程路由；新规则不写进这里 |
| 检索层 | `references/00-catalog.md` | 每张规则卡一行：ID、触发、一句话约束 |
| 规则卡 | `references/<分类>.md` | 按分类存放，唯一允许随时间增长的规则层 |
| 流程 | `references/flow-*.md` | 按顺序执行的清单，不进 catalog |
| 风格包 | `references/styles/<id>.md` | 一种风格一个文件，在 `styles/00-index.md` 登记 |
| 脚本 | `scripts/` | 可直接运行的工具；改脚本必须同步改指向它的卡，并实跑一次 |

## 规则卡格式

```markdown
### <ID> · <短标题>
- 触发: <什么处境下读这张卡>
- 规则: <必须 / 禁止 / 默认 / 先…再… 的可检查约束>
- 为什么: <根因；机制反直觉或有实测数据时必填>
- 验证: <可选：怎么确认做到了>
- 来源: <可选：外部资料的链接；收录外部规则时必填>
```

`触发`、`规则` 必填。机制类卡可在卡末加代码块，反例标 `✗`、正解标 `✓`。

## ID 规范

格式 `<前缀>-<三位序号>`。序号在前缀内只增不复用，删卡保留空号。

| 前缀 | 文件 | 主题 |
|---|---|---|
| `HF` | `hyperframes.md` | HyperFrames 版本、调用方式、契约与环境回收 |
| `DET` | `determinism.md` | 画面确定性 |
| `CRAFT` | `craft.md` | 分镜、风格取用、文字、节拍、多场景一致 |
| `AUD` | `audio.md` | 配乐与音效 |
| `FONT` | `fonts.md` | 字体 |
| `MANIM` | `manim.md` | Manim 数学讲解档 |

一条规则只有一张卡。别处需要时写「见 `<ID>`」，禁止复制规则正文。新增前先查 catalog，确认没有重复或矛盾。

## 风格包格式

文件名为 `<id>.md`，id 用小写英文加连字符，描述风格本身，禁止用人名、品牌名、原作作品名。必须按顺序包含以下标题：

1. 标题行 `# <id> · <中文名>（<英文名>）`，下接元信息表，字段为 `id`、`渲染层`、`画幅`、`时长`、`BPM`、`适用用途`、`状态`、`证据`
2. `## 风格语法`：可迁移的规则，写数值不写形容词；至少含配色（hex、角色、使用阶段）、字体（取自 `fonts.md` 登记表，写 1080p 字号）、运动（时长、缓动、量化）、镜头、声音
3. `## 参考节拍（仅示例）`：原作的时间结构，标明只借节奏与手法
4. `## 题材禁用清单`：原作的具体物件、名称、文案
5. `## 技术配方`：按本 Skill 的渲染层写实现步骤；写进来的代码与参数须在锁定版本上实测过，实测结果写在对应步骤里
6. `## 风格提示词`：用 `{槽位}` 表示题材相关内容，不含原作题材
7. `## 翻车点`
8. `## 验收清单`：能在抽帧或成片上检查的条目

证据等级：「观察」指从画面、面板文字或音频测量直接得到；「推断」指对实现方式的猜测；未经本机实测的写法不得写进技术配方。

## 增改流程

- **新增规则卡**：写卡 → 在 catalog 加一行 → 运行 `check.sh` → 按技能优化循环做盲测。
- **新增风格包**：
  1. 拆解素材，记录观察与推断；
  2. 按上面的格式写包，状态为 `草稿`；
  3. 在 `styles/00-index.md` 登记；
  4. 运行 `check.sh`；
  5. 换题材盲测：只给执行者 Skill 路径和一个与原作无关的题材，按包内验收清单与 `CRAFT-003` 判定；
  6. 通过后状态改为 `已盲测`。
- **改风格包数值**：须附新的观察证据或盲测结论。
