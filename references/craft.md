# CRAFT · 制作规则

规定从需求到画面的做法：先构思再分镜、风格只从风格包取、文字可读、节拍对齐、多场景一致，品牌参数与标志取自品牌目录；节奏、衔接、镜头与快速移动；参考片拆解、产品界面复刻、科普讲解与画面事实核对。

### CRAFT-001 · 先分镜，用户确认后再写代码
- 触发: 开始一支新视频
- 规则: 写代码前先交给用户一份分镜表，得到明确确认再实现。分镜表每行一个节拍，列为：片内时间（秒，按 `CRAFT-005` 写到半拍）、画面、动作、收尾（这一拍怎么结束，见 `CRAFT-010`）、衔接（跨过分界的元素，见 `CRAFT-011`）、文字（标出字数与可见秒数，见 `CRAFT-004`）、要点（这一拍讲明白的一件事，最多引入一个新术语）、音效。表头写明用途、总时长、画幅、帧率、风格包 id、渲染层（HTML 或 Manim）、选定构思（`CRAFT-009`）与节奏数（`CRAFT-010`）；表后附事实清单（`CRAFT-018`）。用户只给了一句话需求时，先问清用途、时长、画幅、要出现的文字，再写分镜
- 为什么: 成片后再改节拍，要连带改动效、音效和字幕的时间；Danny Stuart（2026-09-25）用 Opus 5.5 做宣传片时在 prompt 里要求先做分镜，同时记录到模型不会主动把分镜交给人审，所以这一步必须写成硬规则
- 验证: 对话里有用户对分镜的确认；成片节拍与分镜时间差不超过 0.2 秒
- 来源: https://dannystuart.substack.com/p/claude-code-opus-remotion-agentic-promo-video

### CRAFT-002 · 视觉决定只从风格包取
- 触发: 选配色、字体、缓动、镜头、质感
- 规则: 先在 [styles/00-index.md](styles/00-index.md) 选定一个风格包，配色、字体、节奏、镜头、质感都照包里的「风格语法」取值；项目有品牌目录时，强调色、字体与标志按 `CRAFT-007` 从品牌目录取，其余照风格包。用户没指定风格时，按用途从索引推荐 1–2 个包让用户选。没有合适的包时，先和用户对齐风格方向，把配色 hex、字体、缓动参数写进分镜表头，再动手。禁止凭记忆临时编风格。
  - 用户给了品牌色，或按 `CRAFT-007` 从品牌目录读出了强调色：先算它的相对亮度，替换色板里相对亮度最接近的一格，这一格可以是底色；明暗结构保持不变，也就是深底仍是深底、浅字仍是浅字。替换后按风格包的文字配色规则重算对比度，不低于 4.5:1 才用。品牌片头的收尾底色可以换成品牌色，前提同样是明暗结构不变。
  - 品牌色与风格包的明暗结构冲突时（如 `fui-hud` 要求近黑底上的高亮线条，而品牌色很暗），把冲突告诉用户，给两个选项：换风格包，或只把品牌色用在收尾字标上。
  - 品牌 `DESIGN.md` 限制彩色（如彩色只用于链接与状态）或禁用渐变，而候选风格包是高饱和配色或带渐变暗角时，直接改用 `light-launch`（黑白灰加一个强调色、无渐变），不必向用户提问。
  - 题材物件有公认的固有色（青柠的绿、可乐的红）而色板里没有时，可以把这一种颜色加进色板，只用于该物件。
- 为什么: 没有风格约束时，模型会退回同一套默认审美：渐变底、居中大字、元素全部淡入、结尾放 logo（Movez，2026-09 在 X 上的总结，原文为付费内容，未核实）。两次测试都按「只用色板」把青柠画成明黄，看起来像柠檬。墨绿 `#2F5D50` 若按「先换强调色」放在近黑底上只有 2.47:1；按相对亮度替换群青蓝（0.090 对 0.078）后字幕对比度 6.48:1。品牌 `DESIGN.md` 规定彩色只表示链接、焦点与状态、界面不用渐变时，`shape-morph` 的群青、橙红底与暗角只能交回用户决定
- 验证: 成片的配色、字体与所选风格包的「风格语法」逐项对得上

### CRAFT-003 · 题材与文案来自用户，参考节拍只是示例
- 触发: 写分镜里的物件、剧情与文案
- 规则: 题材、主体、品牌来自用户需求。文案按这个顺序取：用户原话 → 仓库的 README、CHANGELOG、品牌 `DESIGN.md` → 从前两者提炼的功能性文字（场景名、副标、标签）；分镜「文字」列每条注明取自哪一级。禁止自造数字、用户评价、与竞品的比较（`CRAFT-018`）。风格包叙事骨架要求的台词（问题句、解决句）算第三级，只从产品功能提炼。风格包里「参考节拍」一节描述的是原作结构，只能借用其节奏与手法（如「每场景 1.2 秒、形变 0.25 秒」），禁止照搬其中的具体物件、剧情和文字。写完分镜后逐行对照风格包的「题材禁用清单」，命中就改
- 为什么: 拆解 15 种风格时，15 条风格提示词即使经过核验改写，仍有 11 条保留了原作剧情（如开宝箱、猫的情绪剧本）。同一道青柠记账题，一次盲测自拟了副标「个人记账 · PERSONAL FINANCE」，另一次认为副标必须来自用户而只放字标；从 CHANGELOG 与 README 取的文案判定为有出处
- 验证: 分镜表里不出现风格包「题材禁用清单」中的任何名词；「文字」列每条都注明了来源级别

### CRAFT-004 · 文字大小与安全区
- 触发: 排版画面上的文字
- 规则: 画面宽 1080px（竖屏 1080×1920、方形 1080×1080）时：主标题不小于 84px，辅助文字不小于 44px；关键文字离左右边至少 80px、离上下边至少 100px。横屏 1920×1080 沿用同样的像素下限（来源只给了 1080 宽的数值，横屏在手机上显示得更小，这是下限不是目标）。风格包可以为装饰性小字（HUD 标签、数据流）另定更小字号，但必须在包里写明具体数值。每个需要被读的文字元素，完整可见时长不少于 max(1.0 秒, 汉字数 ÷ 7 + 拉丁字符数 ÷ 17)：汉字数含全角标点，拉丁字符数含空格与半角标点；打字机效果从最后一个字出现时起算。字幕与说明文字每行不超过 16 个汉字或 42 个拉丁字符，同屏不超过 2 行
  Manim 档按墨迹高度核对：1 个场景单位 = 画面像素宽 ÷ 14.22（默认画面宽 14.22 个单位；1920×1080 为 135px，1080×1920 竖屏约 76px，同样的场景坐标在竖屏里小得多），墨迹高度 = `mobject.height × 该值`。一行汉字的整体墨迹高约为字号的 0.92–0.97，所以主标题的汉字墨迹不小于 77px、辅助文字不小于 40px；公式里的数字墨迹约为字号的 0.66，作辅助文字时不小于 29px。安全区用 `mobject.get_left()` 等边界坐标换算成像素核对
- 为什么: 视频多数在手机上看，按网页习惯的 28–32px 字号在手机上读不清。Manim 的 `font_size` 与 CSS 像素不对应：两次 Manim 盲测实测 `Text` 字号 48 的汉字墨迹为 79–88px，`MathTypst` 字号 48 的数字墨迹 45–46px（em 约 70px）。汉字比例 0.92–0.97 为 Edge 中 Noto Sans SC 400/900 在 100px 下的实测。竖屏换算为本机实测：`--resolution 1080,1920` 下半径 1.5 的圆直径 230px，即每单位约 76px。阅读速度取 Netflix 简体中文与美国英语字幕规范里儿童节目的上限（7 字/秒、17 字符/秒；成人节目为 9 与 20），每行字数取同两份规范（16 个汉字、42 个字符、最多 2 行），2026-10-07 核对原文：片子里画面同时在动，观众多半不懂技术，按儿童档算。一条 14 个汉字的字幕按 1 秒下限只需停 1 秒，按本条公式要停 2 秒
- 验证: 分镜「文字」列的可见秒数不小于公式值；在 `snapshot` 抽帧上确认主标题与辅助文字未被裁切、未压到安全区；Manim 档在场景里打印关键文字的墨迹高度与边界
- 来源: remotion-dev/skills `skills/remotion-create/video-layout.md`（2026-09-30 核对原文）；https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide ，https://partnerhelp.netflixstudios.com/hc/en-us/articles/217350977-English-USA-Timed-Text-Style-Guide

### CRAFT-005 · 事件卡在节拍网格上
- 触发: 安排画面事件和音效的时间点
- 规则: 先定 BPM，默认 120（风格包另有建议值时用包里的值）。一拍的帧数 = 60 × fps ÷ BPM；30fps、120 BPM 时一拍 15 帧，半拍 7.5 帧。硬切、揭示、落地、重击这类关键事件放在整拍或半拍上，并与音效同帧（见 `AUD-002`）。拍点不落在整帧上时，帧号取 `floor(t × fps)`（如 7.25 秒取第 217 帧），音效时间写成 `帧号 ÷ fps`，画面与音效用同一个帧号。分镜表的时间列写到半拍精度（如 0.25、7.25），关键事件在后面括号注明帧号
- 为什么: 拆解的 15 段作品里，15 段中有 10 段的配乐在 117–120 BPM；9 处硬切里 7 处与音频起音相差不超过 30ms。统一向下取整后，画面与音效只要用同一个帧号就不会差 1 帧
- 验证: 分镜表的关键事件时间都能被半拍整除；`cues.json` 里的事件时间等于分镜注明的帧号 ÷ fps

### CRAFT-006 · 多场景共用一套 token
- 触发: 视频有两个及以上场景，或拆成多个子组合
- 规则: 配色、字号、间距、描边宽度、常用时长与缓动集中定义一次（CSS 变量或一个 JS 常量对象），各场景只引用 token，禁止在场景里重复写字面量
- 为什么: 分场景分别生成会漂移；Roboto Studio 审计 4 个场景，同一角色的字号在 14–19px 之间，间距在 2–22px 之间
- 验证: `grep -cE "#[0-9a-fA-F]{6}" index.html` 的命中只集中在 token 定义块
- 来源: https://robotostudio.com/blog/how-to-use-remotion-agent-skills-with-claude-code

### CRAFT-007 · 品牌参数取自品牌目录
- 触发: 视频项目所在仓库的根目录有 `brand/DESIGN.md`，或用户给出了品牌目录
- 规则: 先读品牌目录里的 `DESIGN.md`，确认唯一参数来源、字体配置与资产映射。强调色、字体、Logo 只从这里取，不再向用户要品牌色或 logo。
  - 颜色：用命令从 tokens 读出本片用到的颜色角色，生成 CSS 变量，禁止手抄 hex。参数来源是 profile-2 格式的 `tokens.json` 时，在视频项目根目录运行下面的命令，第一个参数是品牌目录（视频项目在默认位置 `promo/<slug>/` 时为 `../../brand`），其后是 `meta.roles` 里的角色名。角色名不带后缀时读默认模式（`meta.defaultMode`）的值，变量名为 `--brand-<角色>`（角色名里的点换成连字符）；带 `@<模式>` 时读该模式的值（profile-2 为每个非默认模式生成 `tokens.resolved.<模式>.json`），变量名加 `-<模式>` 后缀，如 `text.primary@dark` 生成 `--brand-text-primary-dark`。深色底上的字标与文字用暗色模式的 `text.primary`，就取 `text.primary@dark`：
    ```bash
    node -e 'const p=require("path"),[b,...roles]=process.argv.slice(1),d=p.resolve(b),t=require(d+"/tokens.json");for(const a of roles){const[k,m]=a.split("@"),f=!m||m===t.meta.defaultMode?"tokens.resolved.json":`tokens.resolved.${m}.json`;console.log(`--brand-${k.replace(/\./g,"-")}${m?"-"+m:""}: ${t.meta.roles[k].split(".").reduce((o,s)=>o[s],require(p.join(d,f))).$value};`)}' ../../brand accent onAccent surface.default text.primary text.primary@dark
    ```
    输出放进组合第一个 `<style>` 的 `:root` token 块（`CRAFT-006`），区块照下面的样子写：起止标记各自单独成行、逐字照写；起始标记的下一行是一条注释，内容是这次运行的完整命令（含 `node -e` 脚本原文）；其余行只放命令输出。tokens 改了就重跑，整体替换两个标记之间的内容。
    ```css
    /* brand:tokens */
    /* <完整命令> */
    --brand-accent: #1A1D22;
    --brand-text-primary-dark: #F6F7F9;
    /* /brand:tokens */
    ```
    参数来源是其他格式时，按 `DESIGN.md` 写明的文件与字段，同样用命令读出，区块写法相同。`check.sh <视频项目目录>` 在上级目录有 `brand/DESIGN.md` 时检查这个区块存在、标记与命令注释的写法；品牌目录是 profile-2 tokens 时，再按上面的命名逐个核对变量值。
  - 读出的 `--brand-accent` 就是 `CRAFT-002` 里的品牌色：按 `CRAFT-002` 决定它替换色板的哪一格，那一格的 token 写成 `var(--brand-accent)`，不再写色值。
  - 字体：`DESIGN.md` 字体配置里的家族，按 `FONT-001` 的品牌字体做法引入。
  - 字标与 Logo：从资产映射取母版，用法见 `CRAFT-008`。
- 为什么: 手抄 hex 让每份物料各存一份色值，品牌改色后各份不会一起变。一个产品仓的宣传片目录里，共用脚本与页面就各手抄了一份品牌色值
- 验证: 重跑区块注释里的命令，输出与区块内容逐行一致；`check.sh <视频项目目录>` 没有 `CRAFT-007` 报错；被品牌色替换的色板格写的是 `var(--brand-…)`，不是色值

### CRAFT-008 · 字标与 Logo 用母版路径
- 触发: 画面里要出现产品的字标或 Logo
- 规则:
  - 有母版时（品牌目录资产映射里的 SVG 母版，或用户给的 SVG 标志文件）：把母版的路径连同 `viewBox` 与 `transform` 原样内联进组合，按母版里已有的 `<path>` 或 `<g>` 拆成可以单独动画的部分。一条复合路径要逐字拆时，按子路径（`M`/`m` 起头的一段）拆：拆出的段若以相对 `m` 开头，先换算成绝对 `M`，否则会移位；带内孔的字形（o、a、e，中文的口字形等）把内孔与外轮廓留在同一条 `<path>` 里，否则内孔会被填实。动画只改 transform 与不透明度，或从别的形状形变到母版路径；定格帧上每条路径的 `d`、相对位置与母版一致，颜色用资产映射里与当前底色对应的色版。禁止用字体重新排出字标，禁止改大小写、字距与曲线。
  - 尺寸与留白按品牌：标志在成片里的尺寸不小于资产映射写的最小尺寸，四周留白不小于品牌规定的安全区，都按成片像素核对；与风格包的字号、构图冲突时以品牌为准，改构图，不改标志。
  - 没有母版：可以按风格包的字体排一个字标，分镜表头与交付说明都写明「临时字标」，并告诉用户正式标志由 visual-system 技能制作；拿到母版后按本卡替换。
- 为什么: 字标的拼写、字距与曲线本身就是品牌资产，用字体重排出来的是另一个标志。风格包给的字标字体（如 `shape-morph` 的 Outfit 800 全小写）只用于还没有正式标志的情形
- 验证: 定格帧里每条标志路径的 `d` 与母版逐条比对一致；在成片抽帧上量标志尺寸与四周留白；没有母版时分镜表头写有「临时字标」

### CRAFT-009 · 先出三个构思，再写分镜
- 触发: 做宣传片（含品牌片头、发布 teaser）、发布片或科普讲解片，用户没有给出画面构思
- 规则: 写分镜前先给三个核心想法不同的画面构思，每个写五项：一句话构思；开场钩子画面；靠什么跨过段落分界（`CRAFT-011` 的手法）；排除了什么；配色方向（风格包 id）。科普片加第六项：结论由前面哪几个已出现的物件排出来。三个构思的类型各不相同，从这几种里选：一个元素贯穿变形、穿越尺度的镜头、前后对照、因果链、物理隐喻、连续表面、版式系统。三个构思与风格包推荐（`CRAFT-002`）放进同一条消息，让用户一次选定，再按 `CRAFT-001` 确认分镜。
  - 片子的结论用画面里已出现过的物件排出来，禁止靠最后补一行说明文字点题；想法读不懂时改画面，不加标签。
  - 风格包规定了叙事骨架或构思类型的（`fui-hud` 开机到关机、`mascot-story` 登场到落版、`shape-morph` 只能是一个元素贯穿变形），三个构思只在骨架内变化：类型可以相同，物件链、开场钩子与收尾方式必须各不相同。
  - 没有人可以确认时，自己选一个，把选定构思与理由写进分镜表头；另外两个在交付说明里各写类型、一句话构思与落选原因，不必写全五项。
- 为什么: onetake 一支照模板节拍做的演示片，衔接得分 1.00（`CRAFT-011`）仍被审片人退回，理由是与前一支太像、没有创造力；one-dot 由三个构思选出，6 个分界全部承接；knockon 的用户没有想法，三选一后首稿通过。overlap 首稿加标签解释反而更难懂，把「&」藏进两张印版、套准时才显现后读懂；pith 首稿八项指标全过，仍被指出结论不在画面里，改成七个方块排成一行（作者自述，1 位审片人）
- 验证: 对话里有三个构思与用户的选择；无人可问时分镜表头写有选定构思与理由；科普片能指出结论画面由哪几个已出现的物件组成
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录；只取方法与数值）

### CRAFT-010 · 节奏：有长有短，有真停顿
- 触发: 写分镜、中途检查、验收成片
- 规则:
  - 节拍时长：只算画面内容不同的节拍行，停顿拍算一行，开头空白与落版定格不算。变异系数（标准差 ÷ 平均值）不小于 0.25，最长一拍不短于最短一拍的 4 倍。用 `python <skill>/scripts/analyze.py beats <这些行的起点,…,最后一行的终点>` 计算，两个数写进分镜表头。
  - 停顿：至少一拍是不短于 1.0 秒的停顿，这一拍里主体不动，镜头不推、不漂、不抖（`CRAFT-012`）。片长不超过 20 秒时，停顿拍、开头空白与落版定格合计不少于片长的 25%，合计秒数写进分镜表头。
  - 收尾方式：分镜「收尾」列写这一拍怎么结束（弹出、离场、硬切、被下一拍吞掉、变形成下一拍），相邻两行不相同。
  - 快切段（可选）：概念里有重击时才用，1.5 秒内至少 3 次大变化；文字快切每个词 0.22–0.36 秒，拉丁字母全大写；一片里有多段快切时，段间间隔不相等。
  - 成片实测：`python <skill>/scripts/analyze.py rhythm renders/<name>.mp4 --beats <同上>`，`longest_low_energy.s` 不小于 1.0；`still_ratio` 不小于 0.25（片长不超过 20 秒）或 0.08（更长）。
  - 风格包在「风格语法」里声明了节奏例外的，被声明的那几项按包。
- 为什么: onetake motion-web 第一版九张卡各 0.74 秒、第二版七个镜头各 1.55 秒，都被判像 PPT；第三版镜头 0.22–2.2 秒、变异系数 0.78 通过；one-dot、knockon、clearing、pith 的变异系数为 0.44、0.67、0.36、0.51，均通过。clearing 首次渲染的停顿段带慢推，静止占比 0.178 被判不合格，改成真静止后 0.294（以上作者自述）。2026-10-07 用 `analyze.py rhythm` 测 onetake 仓库里 10 支已验收成片：15–21.5 秒的 9 支 `still_ratio` 0.257–0.626，30 秒发布片 0.092；`longest_low_energy` 1.0–6.5 秒；被否的 motion-web 第一版作者测得 0.02。本 Skill 已有成片：`shape-morph` 0.51–0.65，`fui-hud` 0.10–0.42，`mascot-story` 因全屏颗粒读成 0
- 验证: 分镜表头写有变异系数、长短比与计划静止秒数；`analyze.py rhythm --chart` 的能量图上，停顿拍所在行的静止比例为 100%
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录与成片；只取方法与数值）

### CRAFT-011 · 段落分界要有元素跨过去
- 触发: 写分镜里两段之间的转换；验收成片
- 规则:
  - 分界指约 0.4 秒内画面大部分换了内容的时刻。舞台常驻、只在局部换内容的片子，`analyze.py rhythm` 测不出分界（`boundaries_s` 为空），这时以分镜相邻两段的交界为分界，照样计分、照样拼分界联系表。分镜「衔接」列给每个分界写出跨过去的元素，以及它在分界处做什么（移动、缩放、变形、打开）；两个元素接力时写清是哪两个。
  - 跨过去的元素在分界处移动不少于画面对角线的 2%（1080p 约 44px）或缩放不少于 10%，记为承接；占画面不少于 3% 且不动，记为锚定。（承接数 + 锚定数 ÷ 2）÷ 分界数不低于 0.5；一镜到底、没有分界的片子不算这一项。一个分界上没有元素跨过去，就是翻页。
  - 硬切只用在快切段内部与切到落版。两个无关场景之间的淡入淡出或滑动不算衔接；一次只显示一个场景、其余全部隐藏的结构，节奏合格也是翻页。
  - 可选手法：按下的东西长成结果（容器变形）；从主体张开舞台；镜头推进穿过一张卡；主体沿弧线跳到下一格；一群元素收拢成标志；光标跨过它引起的分界；尺度推进；因果链；线条变成下一幕的网格线；产品自身主题一帧翻转；主体落到字标母版的位置（`CRAFT-008`）。
  - 风格包规定了转场的（`shape-morph` 一形贯穿与圆形揭示、`mascot-story` 同一布景与缩小退场），按包做的转场计为承接，落在这些转场上的 `hard_cuts_s` 放行；「衔接」列照样填写。
- 为什么: onetake 的 Pocket Weather 第一版节奏指标全部合格，但每一拍都替换掉上一拍，衔接得分 0.00，被判像 PPT；第二版 0.40，只保留了前 6 秒；第三版 0.75 通过；motion-web 第三版 0.56（5 个承接、4 个断开）通过；one-dot 6 个分界全部承接（作者自述，4 个版本标定门槛，1 位审片人）
- 验证: 按 `flow-verify.md`「分界与硬切」一步拼分界联系表，每个分界前 0.2 秒、分界帧、后 0.2 秒三帧里都能看到「衔接」列写的元素；`analyze.py rhythm` 输出的 `hard_cuts_s` 逐个落在快切段内或切到落版的那一帧，其余的抽帧确认是元素一帧出现，不是场景硬切
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录；只取方法与数值）

### CRAFT-012 · 镜头运动
- 触发: 风格包声明有镜头运动，或分镜里有推拉、跟拍、甩镜头、抖动
- 规则:
  - 镜头写成包住舞台的容器的 transform，是 t 的闭式函数（`DET-001`、`DET-004`）：关键帧写焦点坐标与缩放，焦点线性插值、缩放按对数插值，抖动与手持浮动加在屏幕坐标上。写法见 [styles/light-launch.md](styles/light-launch.md) 技术配方第 4 步。
  - 跟拍：关键帧放在主体约 0.1–0.2 秒后要到的位置，缓动 `sine.inOut`。比主体还快的甩镜头：关键帧先放在主体的落点，缓动 `expo.inOut`。
  - 空底上的镜头运动看不出来，要画一层远景点阵当参照：每 48px 一点，点径 1.4px，用细线色。
  - 落地抖动：每次落地或撞击一个衰减正弦，撞击前为 0，相位取固定种子；幅度 3–16px，衰减率 7–14（每秒），最大幅度给全片最重要的落地；带界面文字的段落取 4px。
  - 手持浮动：两个慢正弦叠加，幅度约 4px，进入停顿段前 0.2 秒内降到 0。停顿段里镜头不推、不漂、不抖。
  - 推近超过约 20 倍时，按「锚点在屏幕上的位置 + 缩放的对数」做关键帧，再反算镜头位置。
  - 主体不出画：分镜写明哪些元素在哪个时间窗内必须完整在画内；每次甩镜头与快速位移前后各用 `snapshot` 抽 2 帧核对。
  - 固定机位的风格包（`shape-morph`、`mascot-story`）不加镜头运动；`fui-hud` 只按包推近一次。
- 为什么: onetake one-dot 固定机位版被评缺少跟拍运镜，换成带提前量的跟拍后通过；one-dot 镜头版首次渲染在 1.10 秒把主体甩出画面，其余指标全过，没有别的检查发现（作者自述）。clearing 停顿段带慢推被判不静（`CRAFT-010`）。0.8.96 上的 10 秒探针实测：镜头按本卡写成闭式函数，`check` 通过；4px 手持浮动在 `analyze.py` 的 320px 缩图上看不出来（浮动段静止比例仍为 100%），在宽 300px、含边缘的区域里按原分辨率测才能区分动与静
- 验证: `python <skill>/scripts/analyze.py motion renders/<name>.mp4 --roi <x,y,w,h> --thresh 0.02`，区域宽不超过 320px（此时按原分辨率分析）并框住带边缘的元素，停顿段内没有运动区间；甩镜头前后的抽帧里主体完整在画内
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录；只取方法与数值）

### CRAFT-013 · 快速移动不靠运动模糊
- 触发: 元素或镜头在一两帧内移动很远（甩镜头、飞入、冲刺、快速换位）
- 规则:
  - 锁定的 0.8.96 下不加运动模糊：不用官方 `motion-blur` 组件；CSS `blur()` 向各个方向一起糊，不算运动模糊；禁止为运动模糊另写逐帧截图渲染器，渲染一律走 HyperFrames（`HF-001`）。
  - 峰值每帧位移 = 移动距离 × 缓动最大斜率 ÷（时长 × fps）。常用缓动的最大斜率（同一族的 `.in`、`.out`、`.inOut` 相同）：`none` 1，`sine` 1.57，`power1` 2，`power2` 3，`power3` 4，`power4` 5，`back.out(1.7)` 4.7，`expo` 6.9。
  - 峰值超过 80px/帧（按 1920 宽、30fps；60fps 时为 40px）的动作，分镜「动作」列写明用哪种处理：① 压到 2 帧以内当作位置硬切，落点停住；② 加风格化残影，主体副本 6–8 份，逐份延后 0.012 秒、不透明度递减（写法同 `shape-morph` 技术配方第 7 步）；③ 拉长时长或换斜率小的缓动，把峰值降到 80px/帧以下；④ 移动中的文字不要求可读，到位后按 `CRAFT-004` 停够时长；⑤ 风格包写明的挤压拉伸弹跳（`shape-morph`、`mascot-story` 的落下与团块弹跳）按包做，不另加残影。
- 为什么: 按 `HF-005` 查到 v0.8.96 tag 下的 `skills/hyperframes-animation/references/motion-blur.md` 与 `registry/components/motion-blur/`：组件在页面里沿轨迹叠 N+1 份副本模拟快门，靠 `setTimeout` 轮询挂载（与 `DET-001` 冲突）。本机 0.8.96 实测同一组合连续渲染 6 次（`--workers 2`；属性挂载、显式 `attachMotionBlur`、关闭 fast capture 各 2 次），3 次有拖影、3 次没有，交替出现；引擎自带的子帧运动模糊不在 CLI `render` 的参数里。80px/帧是 onetake 作者的工程判断，没有审片结论：motion-web 与 Pocket Weather 第三版不带模糊，峰值 385、354px/帧（作者口径）照样通过，所以超过阈值时要求选定一种处理，而不是一律禁止。GSAP 的 `power1`–`power4` 依次是二次到五次曲线，最大斜率为 2–5。收尾团块一跳 260px、0.125 秒 `power2.out`，峰值 208px/帧，目检为正常的卡通弹跳；给吉祥物 0.8 秒落下另加 6 份残影，判定为包外手法
- 验证: 峰值动作前后各 1 帧抽帧，画面与「动作」列写的处理一致
- 来源: https://raw.githubusercontent.com/heygen-com/hyperframes/v0.8.96/skills/hyperframes-animation/references/motion-blur.md ；https://github.com/feitangyuan/onetake （commit cf09bde）

### CRAFT-014 · 强调靠主体自己
- 触发: 想给落地、完成、揭晓或关键词加强调
- 规则: 禁止用粒子、彩纸、碎点、闪点迸发做强调。强调由主体自己完成：落地挤压回弹、缩放冲击、落地抖动（`CRAFT-012`）、颜色或主题一帧翻转、全片唯一的强调色。不是产品自身行为的装饰点缀一律删掉。收拢成标志的线条与形状（如 `shape-morph` 收尾各场景颜色化成短线、汇成句点）是主体自身的变形，不算碎点。风格包写明的常驻质感层与包内装饰（`mascot-story` 的星星、颗粒与火花，`fui-hud` 的数据流与残影）按包
- 为什么: onetake motion-web 字标处的彩纸碎点被审片人评为「低劣」后删除（作者自述，1 次）。若把 `shape-morph` 收尾的短线汇聚当成碎点删掉，收尾会少一个包内动作
- 验证: 抽帧里没有风格包以外的粒子、彩纸或闪点
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录）

### CRAFT-015 · 参考片：先量，再取规则
- 触发: 用户给了参考片，或说「照这个视频的感觉」「像这支一样」
- 规则:
  1. 先量。`python <skill>/scripts/analyze.py rhythm <参考片> --chart` 读静止占比、低能量占比、最长静止段与最长低能量段、瞬变时刻与次数、快切段、分界与段落时长分布，能量图看起伏；`analyze.py ground <参考片>` 读主底色与底色占比。再抽帧看：最大元素占画宽多少、每拍实际在动的是什么、叙事链、入场与离场方式、文字（字号、字重、强调色个数）、缓动快慢。缓动用 t80 描述，即走完 80% 路程所用时间占总时长的比例：`expo.out` 0.23、`back.out(1.7)` 0.24、`power2.out` 0.42、`expo.inOut` 0.57、`sine.inOut` 0.70、`none` 0.80。这些读数写进分镜表头，作为对齐目标。
  2. 取规则，不取画面。找出每个物件都遵守的那条规则；分清做出这种风格的工具留下的签名效果与顺手效果；颜色从整帧取 hex，网格在一行上量，字高在 1080p 上量大写字母；参考片的硬切位置不属于风格。
  3. 参考片里的物件、文案、叙事顺序当作题材禁用清单（`CRAFT-003`），节拍来自三构思（`CRAFT-009`）。
  4. 参考片对得上某个风格包时用这个包；对不上时按 `CRAFT-002`「没有合适的包」路径，把量到的数值写进分镜表头。
  5. 参考片只用来分析，它的帧图不进成片，也不进交付物。
- 为什么: onetake motion-web 前两版没有量参考片，两次都做成等长节奏，量过之后第三版通过；一次第三方作品的风格复刻在第 1 稿就被叫停，理由是照搬复刻没有意义（作者自述）。本 Skill 用 `analyze.py` 量 motion-web：静止 0.531、低能量 0.827、最长静止 1.67 秒、瞬变 11 次（含 13.25–14.3 秒的快切段）、主底色 `#f6f7f5`、底色占比中位数 0.98，静止与低能量读数与作者口径相差不超过 0.01
- 验证: 分镜表头有参考片的量化读数；分镜与成片里没有参考片的物件与文案
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的案例记录与成片；只取方法与数值）

### CRAFT-016 · 产品界面用 HTML 复刻
- 触发: 宣传片要展示软件产品的界面或操作
- 规则:
  - 界面在组合里用 HTML 重建，依据是用户截图或仓库前端代码；录屏素材剪辑不在本 Skill 范围内。向用户只提一个具体请求：「打开 X，点 Y，每一步截一张图」；无人可问时用仓库里的截图与前端代码。
  - 画面里的数据、文件名、数字只用产品的真实输出：由脚本从仓库样例数据或产品产出的文件读出，不手打；做不到时在画面上标「示意」（`CRAFT-018`）。账号名、邮箱、头像等个人信息隐去。
  - 按截图自己的像素坐标绝对定位（Retina 截图坐标先折半），整体乘复刻缩放 s 放进画面里的窗口；每个界面状态写成一个纯函数，由时间线或 `render(t)` 调用（`DET-004`）；复刻用的 CSS 全部挂在一个根类名下；需要量尺寸的元素在字体加载后、元素可见时量（写法同 `mascot-story` 技术配方第 1 步）。
  - 产品用系统字体时换成登记表里最接近的字体（`FONT-001`），交付说明写明替换了什么。
  - 屏幕字号 = 界面字号 × s × 镜头缩放。被字幕或标注点名的界面文字，屏幕字号不小于 44px（`CRAFT-004` 的辅助文字下限），不够时靠推近（`CRAFT-012`）；要读的窗口占画宽 70–80%；没被点名的界面文字算装饰性小字。
  - 一个操作一个特写，镜头跟着光标在特写之间移动；全景只用在部件之间的关系本身就是重点时。光标点在元素中心，按下到抬起 60–75ms，按下时指针缩到 0.84 倍。要提前展示结果时开一个画中小窗，不切走再切回。
  - 禁止把整页缩成小卡片指望动效可读：要么整屏显示且光标可见，要么只把一个组件放进卡片里实时运行。
- 为什么: onetake 产品演示的记录（作者自述）：给非技术用户一份镜头清单，用户回复看不懂要录什么；复刻 CSS 与组合样式的类名冲突，画出一圈黄色虚线框；切走再切回被读成两次硬切；把卡片、窗口、结果塞进一个全景的版本因看不清被退回；motion-web 第一版九张整页缩略卡（约 700px 宽、各停 0.74 秒）被判像 PPT。按本卡的算式，13px 的界面标签在 0.75 倍复刻里要推近约 4.5 倍才到 44px
- 验证: 在特写抽帧上量被点名文字的字高；画面里的数据都能追溯到仓库文件，或标了「示意」
- 来源: https://github.com/feitangyuan/onetake （commit cf09bde 的 product-demo 记录；只取方法与数值）

### CRAFT-017 · 科普讲解片
- 触发: 给非技术观众讲一个技术机制或原理，画面不以公式推导为主
- 规则:
  - 渲染层用 HyperFrames（`MANIM-001`）；用户没指定风格时用 `light-launch`，图解按包里的「图解」一节。不做旁白，信息只靠画面文字与字幕，字幕按 `CRAFT-004` 停够时长。
  - 30–60 秒默认 5 段：① 问题上屏，不超过 3 秒，一句疑问；② 一个比喻，1 拍；③ 机制 3–5 拍，每拍引入一个新概念；④ 回到开头的问题，给出答案；⑤ 一句结论，完全静止定格不少于 2 秒。分镜表头写各段时长。
  - 一拍讲一件事：「要点」列（`CRAFT-001`）每拍一句，最多引入一个新术语。
  - 关键词作为标签贴在它所指的图形旁边，不只放在底部字幕里，用强调色或字重标出；同一个概念全片用同一种颜色（语义色 token，`CRAFT-006`）。
  - 比喻全片不超过 2 个，每个至少占 2 拍：一拍引入，一拍对应到真实部件；对应关系与「在哪里不成立」写进事实清单（`CRAFT-018`）。
  - 图解动作默认 4 种：逐步搭建；只亮当前部件，其余降到 40% 不透明度；放大进入内部，用同一元素的缩放完成衔接（`CRAFT-011`）；拆分与合并。
  - 结论画面由前面已出现的物件排出来（`CRAFT-009`）。
  - 声音默认「轻」配乐加少量起音型音效（`AUD-005`），不必向用户提问。
- 为什么: 标签贴近图形、关键处加提示、一段只讲一个概念，对应 Richard E. Mayer《Multimedia Learning》第 2 版（剑桥大学出版社，2009）的空间邻近、提示与分段原则。数学讲解没有风格包时，三轮测试的执行者各自现编了一套配色（一轮借 `shape-morph` 色板，两轮各用一套深底蓝金），非数学科普同样没有骨架与配色可依
- 验证: 分镜表头有 5 段时长，「要点」列每拍一句；抽帧里关键词标签贴在所指图形旁；结论定格段在 `analyze.py rhythm --chart` 的能量图上静止为 100%

### CRAFT-018 · 画面事实清单
- 触发: 画面上出现断言、数字、产品功能描述、机制描述或比喻
- 规则: `storyboard.md` 末尾加「事实清单」表，画面上的每条断言、数字、机制描述占一行，列为：画面文字、出处（用户原话；仓库文件路径与行号；具名公开文档加链接）。没有出处的数字改写成不带数字的说法，或在画面上标「示意」。比喻另加两列：对应关系（比喻物 ↔ 真实部件）、在哪里不成立；不成立的地方会误导结论时，画面加一行修正字幕。画面上没有任何断言时写「事实清单：无」
- 为什么: 一次盲测给真实产品 Sentinel Review 自拟了「Go 单仓 48,213 个文件、9.6M 行」和一个具体的文件行号；`fui-hud` 的版式要求大读数与候选列表，题材里没有真实数据时执行者就会编
- 验证: 成片抽帧上的每条文字都能在事实清单里找到出处或「示意」标记；`check.sh <项目目录>` 检查 `storyboard.md` 里有「事实清单」
